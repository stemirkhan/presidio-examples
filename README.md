# Presidio: от распознавателей до CrewAI и LiteLLM

Исполняемые примеры к видео о Presidio: поиск и замена персональных данных,
подключение Fastino и Metrika, устойчивые метки, восстановление значений,
агент на CrewAI и интеграция через LiteLLM Proxy. Все входные данные вымышлены.

## Быстрый старт

Проверенная среда: **Linux / WSL, Python 3.12, CPU**. Нужен установленный `uv`.
Нативный Windows не поддерживается: журнал бюджета использует `fcntl`,
а команды и конфигурации IDE — пути `bin/python`.

```sh
git clone https://github.com/stemirkhan/presidio-examples.git
cd presidio-examples
python3.12 setup_environments.py
.venv/bin/python prepare_models.py
.venv/bin/python d01_basics.py --step
```

Установка создаёт три окружения: `.venv` для Presidio, spaCy и GLiNER;
`.venv-agent` для CrewAI; `.venv-proxy` для LiteLLM. Они разделены из-за
несовместимых основных версий MCP. Модели spaCy входят в зависимости core,
а две GLiNER-модели скачиваются отдельной командой в `models/`.
Ревизии весов закреплены в [data/models.json](data/models.json).

Чтобы проверить подготовку без загрузки весов в память и без API:

```sh
python3.12 preflight.py
```

`--step` включает остановки по Enter. Без этого флага скрипт выполняется целиком.

## Примеры

Все команды ниже выполняются из корня репозитория.

| Блок | Что показывает | Команда |
|---|---|---|
| D01 | Analyzer → находки → Anonymizer, русский текст | `.venv/bin/python d01_basics.py --step` |
| D02 | Выбор распознавателей | `.venv/bin/python d02_select.py` |
| D02 | Собственное регулярное выражение | `.venv/bin/python d02_custom.py` |
| D03 | Токены, начальные формы, сущности | `.venv/bin/python d03_nlp.py --step` |
| D04 | Replace, mask, redact на одних находках | `.venv/bin/python d04_operators.py --step` |
| D05 | Штатные распознаватели с русской NLP-моделью | `.venv/bin/python d05_russian_baseline.py` |
| D06 | Адаптер Fastino и Metrika | `.venv/bin/python d06_models.py --step` |
| D07 | Сравнение трёх конфигураций на 20 текстах | `.venv/bin/python d07_comparison.py` |
| D08 | Пропуск JWT и добавление правила | `.venv/bin/python d08_fix.py --step` |
| D09 | Настоящий агент CrewAI | `.venv-agent/bin/python d09_crewai.py --step` |
| D10 | Повторные значения получают ту же метку | `.venv/bin/python d10_pseudonyms.py --step` |
| D10b | Обратная подстановка через свой оператор | `.venv/bin/python d10b_restore.py --step` |
| D11 | Настоящий LiteLLM Proxy | `.venv-proxy/bin/python d11_litellm.py --step` |
| D12 | Просмотр сохранённых результатов без инференса | `python3.12 d12_review.py` |

В PyCharm откройте корень как проект. В `.run/` есть готовые конфигурации с
путями относительно проекта. Для скрытого ввода ключа включите эмуляцию
терминала в конфигурации Run или запустите команду в обычном терминале.

## D09 и D11: сначала локальная проверка

После подготовки весов эти команды проверяют отказ фильтра на настоящих
CrewAI / LiteLLM и локальном Presidio. Ключ и журнал бюджета не нужны;
запрос к AI-провайдеру не выполняется.

```sh
.venv-agent/bin/python d09_crewai.py --check-only
.venv-proxy/bin/python d11_litellm.py --check-only
```

Для полного запуска сначала создайте собственный журнал бюджета:

```sh
python3.12 init_budget.py --limit-usd 3
```

Затем выполните D09 или D11 из таблицы. Скрипт скрыто попросит DeepSeek API key
или прочитает `DEEPSEEK_API_KEY` из окружения. Ключ не записывается в исходники.
Демонстрация использует `deepseek-flash` и реальные платные обращения.
Повторная инициализация существующего журнала запрещена: оба демо используют
один накопительный лимит. Подробнее — [BUDGET.md](BUDGET.md).
Стоимость оценивается локально по тарифам в коде; это не лимит списаний на
стороне провайдера. В этом репозитории новые платные результаты не обещаются
идентичными записанному ответу модели.

Шлюз в `support/gateway.py` сохраняет фактическое тело исходящего запроса,
проверяет известные исходные значения учебного примера и учитывает расходы.
Обезличивание выполняет Presidio. Проверка известных значений в шлюзе не
заменяет поиск произвольных секретов.

## Результаты из видео

[RESULTS.md](RESULTS.md) описывает исторические прогоны, включая ошибки агента.
[evidence/recorded/](evidence/recorded/) содержит выбранные результаты этих
прогонов; [evidence/snapshot.json](evidence/snapshot.json) — их сводку.
Для проверки сравнения без моделей и API:

```sh
python3.12 verify_recorded_results.py
python3.12 d12_review.py
```

На учебном наборе из 20 текстов и 25 размеченных упоминаний полное закрытие:
baseline — 18/25, Fastino — 19/25, Metrika — 25/25. Это не гарантия качества
на других документах. Условия и метрики — [PROTOCOL.md](PROTOCOL.md).

После записи исправлена повторная обработка готовой метки в поле `name`:
известная локальному словарю метка теперь сохраняется при следующем проходе.
Исходный ответ D09 не переписывался; в новом запуске номера меток могут
отличаться. D10/D10b показывают тот же механизм устойчивых меток и отдельного
восстановления. Автоматическое объединение разных написаний имени не реализовано.

Регрессионные проверки без API и без загрузки моделей:

```sh
.venv/bin/python -m unittest discover -s tests -v
```

## Локальные настройки и сохранение запусков

При необходимости скопируйте `local.example.json` в `local.json`. Относительные
пути разрешаются от корня проекта. Локальная конфигурация, ключи, веса,
журнал расходов и новые результаты не входят в Git.

Каждый запуск создаёт новую папку `runs/`. Сохраняются код, версии,
найденные фрагменты, запросы, ответы и проверки. В собственных запусках
эти файлы могут содержать исходные чувствительные данные и локальный словарь
соответствий; не публикуйте их вместе с ключами или реальными документами.

## Границы примера

Это учебная интеграция для одного контекста и нестриминговых
`chat/completions`. Файловые вложения, несколько пользователей и произвольные
форматы tool calls здесь не проверялись. При отказе Presidio запрос
останавливается. Корректное скрытие данных не гарантирует правильного
вывода агента: в записанном ответе сохранены неверный счётчик комментариев
и цитаты из описаний вместо комментариев.
